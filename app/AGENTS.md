# Prototype Instructions

## Accepted product direction (2026-11-12)

- PulseDeck is a Windows desktop application, not only a browser dashboard.
- The user confirmed an animated desktop wallpaper behind desktop icons, with a separate settings/control window and an optional regular display window.
- Keep the wallpaper presentation clean: no parameter drawer, toolbar, buttons, or alerts over the animation. Configure it from the application or tray.
- Ring interiors must resemble the supplied NEXUS video: irregular neural filaments, traveling luminous signals, subtle depth and localized bright computation sectors.
- The circular core and particle field must be visibly connected, including pointer/drag/click reactions and continuous signal discharge from the ring into the field.
- Complete each meaningful stage with a Git commit and push to the existing Unorva/PulseDeck repository. Stage explicit source/document paths; keep screenshots, local logs, build output and telemetry out of commits.
- Latest correction: retain the original bottom six monitoring cards and right-side metric cards in the desktop wallpaper. Clean display means controls stay in Settings; it does not mean removing telemetry cards.
- The three small black holes must attract, bend and capture particles. Use actual shared acceleration, not decorative circles or only preset paths.
- The computation ring should be slightly wider, with fine radial streamlines perpendicular to the rim and continuous normal-direction discharge into the field.
- Black holes must be larger and mutually attract each other. Their positions and velocities evolve from pairwise forces; dragging one changes the other two trajectories as well as the particle field.
- Particle strokes need visible, soft thickness and continuous curved flow. Avoid fixed laser outlets, synchronized emission packets, and disconnected bright spray.
- Latest correction (2026-11-13): desktop wallpaper must visibly render; CPU drives its particle group's speed, memory drives density, GPU and each network direction drive their own speed/density. Match all five groups to the right-hand cards with shared colors. Remove the central English lettering and opaque label plate from the left neural sphere.
- Latest correction: confine the mutually attracting black holes to a bounded central region, including after dragging. Render dark horizons with soft halos, without orbit trails or tilted planetary rings. Particles themselves must travel continuously from the left ring, through the black-hole field, and into their matching metric card; do not draw separate connector lines. Match the wallpaper client surface to each selected monitor's physical full-screen bounds, including mixed DPI, negative screen coordinates and invisible window frame insets; remove wallpaper page gutters and maximum-width limits.
- Latest correction: remove the annular-flow scene. Replace the standalone black-hole scene with a hole-free Signal Stream scene; remove its hidden gravity sink as well as the visible hole. Keep four scenes (Signal Stream, Fusion, Three Body, Inference) consistently in settings, tabs, tray and 1–4 shortcuts, migrating legacy saved mode IDs. Only Three Body renders black holes, without planetary rings. Remove the two upper-left canvas titles shown in the user's screenshot (NEURAL OBSERVATORY and 环状运算中枢), including when instrument labels are enabled.
- Latest correction: black-hole halos follow the selected theme color with soft natural diffusion and smooth color transitions; do not lock them to orange. The left neural sphere responds automatically to each fresh telemetry sample with gentle randomized three-axis rotation and localized traveling node illumination. Keep manual pointer interactions, respect pause, and deduplicate repeated samples; automatic effects must not depend on a click or mouse interaction being enabled.
- Latest correction: the left ring must visibly emit moving light that gradually widens and diffuses along the actual particle routes. Replace dry radial combs and stacked bright vertical rim marks with soft traveling trails, preserving continuity into the field. Use exactly the same per-metric colors for particles, emission trails and the corresponding right-hand card's color marker, across all themes.
- Latest visual reference: restore the earlier circular soft halo around a clean black center, matching the user's cropped reference. Make it clearly visible and broader, preserve theme colors (including the theme's highlight color), and remove crescent-shaped bright arcs and separate photon-ring strokes. Show a substantial moving-particle launch segment along the ring's local outward normal before it diffuses and bends into the field; this is continuous particle flow rather than a static light comb.
- Latest correction: trigger the neural sphere's automatic randomized rotation and illumination once per ten fresh valid samples, deduplicating repeats. Emit discrete glowing particles with tiny tails instead of continuous line/ribbon bundles. Give all five metrics distinct independent speed ranges that respond to their own values. Emission sources must drift continuously around the rim, with density/opacity tapering to zero at both edges rather than a fixed wedge or fixed outlets.
- Latest scene references: Three Body has three closely grouped, bounded, mutually orbiting black holes; multiple particle streams gather through the cluster and fan back out to matching cards. Matrix Compute (the existing neural scene) has six labeled columns (输入编码, 注意力, 并行分支, 层级路由, 汇合, 输出), fine crossing connections and signals traveling through the node columns. Add same-color receiving-point and card-border glow when particles actually arrive at each right-hand metric card; stronger streams should give clearer feedback.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
